## Context
The backend exposes an OpenAPI document (Scalar at `/docs`); the panel needs typed calls that follow
API changes, many list/detail screens, forms with backend-mirrored validation, and a session that is
not a token in `localStorage`.

## Decision
- `frontend/` is a TanStack Start app (Vite, Yarn 4): file-based routes under `src/routes`
  (`routeTree.gen.ts` generated by `tsr generate`), TanStack Query for server state, TanStack Form
  for forms (field wrappers in `src/forms/wrapper.tsx`), Tailwind CSS v4, Biome.
- Server functions under `src/server/` hold the session (cookies) and proxy `/api`.
- The API client in `src/api/endpoints/**` and `src/api/models/**` is **generated by orval**
  (`yarn api:gen` from the running API's `/openapi/v1.json`) and never hand-edited; `src/api/mutator.ts`
  holds the axios instance and `src/api/query-keys/*` are hand-written.
- Feature code lives under `src/features/<area>/pages/{components,hooks}`; shared primitives in
  `src/components/ui`.
- Projection lag is handled in the UI with `useProjectionWait`.
- Pure logic is unit-tested with Vitest; flows with Playwright.

## Alternatives considered
- The first skeleton (`73afcd47`, 2026-09-10) was a plain Vite SPA with `react-router-dom`, a
  `zustand` auth store and hand-written route lists (`routes/routes.ts`). Four days later
  `064a3a9b` replaced the router with TanStack Start file routes and added server-side auth
  (`src/server/auth.ts`).
- Plan 028 (local, not in git, §D.1) re-examined the form library for the dynamic forms and stayed
  with TanStack Form; ready-made form engines were rejected.

## Consequences
- An API change reaches the panel only after `yarn api:gen` against a running, rebuilt API; a stale
  client keeps old fields (e.g. `isEmpty?` on `FieldValue` until regeneration).
- Backend error shapes matter to the client: the reports 503 had to be described as ProblemDetails so
  the generated client had no `void` error (`53446721`).
- Both `#/*` and `@/*` alias `./src/*`; files follow their neighbours.
- TanStack Form reads a dot as a path, so dynamic form controls are named `f_<fieldId>`.

## Revisit when
- The panel needs a client that orval cannot generate (streaming, websockets).
- TanStack Start changes its server function or routing model incompatibly.
