# 011 · Agency panel foundation

**Status:** done · **Built:** 2026-09-03 → 2026-09-19 · **Verify:** `./verify suggestions` · **Plan:** backend 001 (local, not in git)

## Why
Recruiters, sales people and HR work in one web panel. Every screen needs the same things: a typed
client for the API, paged tables that also work on a phone, pickers that find a company, user, tag
or worker as you type, and a way to read back data the API wrote a moment ago. Building these once
keeps each feature screen small.

## What it promises
- The panel is a TanStack Start app; the API client and models are generated by orval from the
  running API's OpenAPI document (`yarn api:gen`) and are never edited by hand.
- Browser calls go through the panel's own `/api` proxy, which attaches the bearer token from an
  httpOnly cookie; server functions load page data on the server with the same session.
- Lists are paged tables with search and filters kept in the URL, with a card list on small screens
  and "load more" paging.
- Suggestion (typeahead) endpoints return companies, company contacts, users (by role), tags (by
  category and/or search), job posts, teams, projects, positions and workers - always only from the
  caller's organization.
- A picker given only an id restores its label by fetching that one item (`GET /api/suggestion/<x>/{id}`);
  an id from another organization answers 404.
- Tags without a search term or category are refused with 400.
- After a write, screens can wait for the async projection before re-reading (`useProjectionWait`).

  `frontend/src/forms/wrapper.tsx`, `frontend/src/hooks/useProjectionWait.ts`.
- Tests: `tests/HrAgencySystem.IntegrationTests.CrossCutting/Suggestion`.

## Out of scope for this feature
- No dedicated `Suggestion` module; suggestion repositories stay in the module that owns the data (not ever).
- Picker fixes P4-P6 from plan 001 (loading indicator, `role` prop leak, clear reopening the list)
  were left optional; contacts/tags/job-post pickers did not get the get-by-id restore.
- `useProjectionWait` does not poll the read model (see notes).

## Decisions
- TanStack Start + Query + Form, orval-generated client: [ADR-0022](../../../docs/adr/0022-frontend-tanstack-start-orval.md).
- Suggestion endpoints follow the thin endpoint-per-file API: [ADR-0008](../../../docs/adr/0008-endpoint-per-file-thin-api.md).
- Every suggestion query is tenant scoped: [ADR-0004](../../../docs/adr/0004-tenant-on-every-aggregate.md).
- Picker label restore by fetching the item by id ("option A" of plan 001) instead of storing labels
  in form state - one source of truth for the label.
- Entity pickers use `allowCustomValue={false}` so a typed letter cannot leave a stale id behind (plan 001, P2).

## Notes from reconstruction
- The panel started as a Vite + `react-router-dom` app served by nginx (`73afcd47`) and was rebuilt
  on TanStack Start four days later (`064a3a9b`), which removed the nginx config.
- `useProjectionWait` is a fixed 1.5 s delay, not a poll of the read model - lag longer than that
  still shows stale data.
- The generic `Kanban` and `FormWizard` primitives in `components/` came from feature work (sales,
  job descriptions) and were lifted out afterwards.
